## 一、总体结论

### 1.1 这些论文主要沿着五类路线展开

| 研究路线 | 主要研究内容 | 常见章节组织 | 代表性论文 |
|---|---|---|---|
| A. 视觉识别/实例分割 | 数据集、目标检测、实例分割、遮挡处理 | 系统与标定 → 数据集 → 检测/分割改进 → 实验 | 焦慧清、欧美彤、解晓民、朱文磊、周鸿敏 |
| B. 6D 位姿估计 | 点云预处理、模板匹配、特征融合、位姿精化 | 系统与标定 → 点云/图像处理 → 位姿估计 → 抓取实验 | 杨宗兴、沈泽鑫、林云森、刘永强、石磊、陈诺 |
| C. 抓取检测/抓取质量 | 抓取候选生成、抓取姿态评价、遮挡下候选筛选 | 系统与数据 → 抓取检测模型 → 对比/消融 → 抓取实验 | 朱文磊、陈佳伟、赵有港 |
| D. 运动规划/避障 | 运动学、手眼标定、碰撞检测、路径规划和轨迹优化 | 机器人建模 → 标定/碰撞 → 规划优化 → 仿真/真机 | 林志昊、谢林清、佟欣、强华 |
| E. 系统集成/数字孪生 | 视觉、机器人、控制、虚拟场景和实体设备联动 | 系统架构 → 各关键模块 → 软件实现 → 综合实验 | 赵伯虎、李云飞、黄铮、强华、唐潘 |

**最重要的共同规律：** 一篇硕士论文通常选择其中一条路线作为研究主轴，其他模块承担输入、系统支撑和实验验证。并不是每篇都从检测、位姿估计、抓取检测、规划、控制、数字孪生全部提出新算法。

### 1.2 软件并不是越多越好

文献中的软件大致承担不同任务：

- **物理/机器人仿真：** MuJoCo、Gazebo、V-REP/CoppeliaSim、Isaac Sim、Bullet、RobotStudio。
- **运动规划和机器人集成：** ROS、MoveIt、RViz。
- **数据合成与渲染：** Blender、BlenderProc。
- **CAD 建模：** SolidWorks、CATIA。
- **点云处理：** PCL、Open3D、CloudCompare。
- **图像处理和标定：** OpenCV、HALCON、MATLAB。
- **网络训练：** PyTorch、TensorFlow。
- **开发环境：** Visual Studio、PyCharm、Qt Creator。

这些工具不能互相替代。例如 BlenderProc 负责合成视觉数据，不等于机械臂物理抓取；RViz 负责机器人状态和轨迹可视化，不等于 Gazebo/MuJoCo 的物理接触仿真；MATLAB Camera Calibrator 主要用于标定，不是完整机器人仿真平台。

### 1.3 对当前课题最有价值的借鉴

建议重点参考四种论文组织方式：

1. **杨宗兴、欧美彤：** 如何组织合成数据、真实数据、RGB-D/深度/Mask、位姿估计网络与定量实验。
2. **陈佳伟：** 如何把 MuJoCo 用于抓取数据生成/抓取质量评价，并与机器人仿真及真机实验区分。
3. **林志昊、佟欣、解晓民：** 如何表达机器人模型、坐标变换、碰撞检查、运动规划与轨迹可视化。
4. **黄铮、李云飞：** 如何把点云建模、点云处理、真实平台与抓取执行组织成系统性论文。

## 二、参考论文的研究路线分类

### 2.1 视觉与位姿估计方向

这一类论文的共同逻辑是：

`相机与系统搭建 → 数据采集/标注 → 图像或点云预处理 → 目标识别/分割 → 位姿估计 → 定量验证`

其图表重点通常包括：
- 相机成像模型、标定板、坐标系；
- 原始 RGB/Depth、分割 Mask、点云滤波前后；
- 网络结构、特征融合流程；
- 点云粗配准/精配准结果；
- 重投影误差、ADD/ADD-S、精度和耗时表。

对当前课题的启示：已有 D435i 和实例分割基础不需要再独立做成一条大创新主线；应把真实视觉链路写清楚，为双侧接触评价提供可信输入。

### 2.2 抓取检测与接触评价方向

典型逻辑：

`目标实例/点云 → 抓取候选生成 → 抓取质量评价 → 候选排序 → 机器人执行`

图表重点：
- 抓取网络输入/输出表示；
- 夹爪几何、抓取框、闭合轴和接近方向；
- 抓取候选可视化；
- 候选质量分布、对比实验和消融表；
- 真机抓取成功/失败过程。

对当前课题的启示：双侧接触评价需要有专门图示，把左右指预计接触区域、局部深度质量、几何连续性和一致性画清楚。否则创新点容易停留在文字层面。

### 2.3 运动规划与避障方向

典型逻辑：

`机器人运动学 → 手眼标定 → 场景点云/障碍物 → 碰撞检测 → 路径规划 → 轨迹优化 → 仿真/真机`

图表重点：
- 机械臂 MDH/DH 模型；
- 相机/基座/TCP 坐标变换；
- 点云加载与碰撞模型；
- RRT/RRT-Connect 搜索树和路径；
- 规划路径、关节曲线、路径长度和规划耗时表。

对当前课题的启示：第四章不应重新开发完整规划器。可以用成熟规划工具完成 IK、碰撞和路径可执行性检查，把研究重点放在候选失败分类和有限修正上。

训练 Loss 曲线只在自己训练或微调模型时需要。若只是调用预训练 GraspNet，不应为了论文强行加入训练曲线。

| **PyTorch** | 视 GraspNet 主模型而定 | 模型推理/必要微调 |
| **MuJoCo** | 必须保留 | CR10A、夹爪、料箱、易拉罐的物理接触、碰撞和抓取过程验证 |
| **Dobot CR10A 控制接口/SDK** | 必须 | 真机运动、状态读取和任务执行 |
| **CAD 工具（已有者优先）** | 必须有模型来源 | 夹爪、料箱和工件几何建模；不要求为论文新购软件 |
| **MATLAB** | 非必须 | 只有现有标定流程依赖时才保留 |
| **ROS/MoveIt** | 条件使用 | 若现有 CR10A 接口可用、且 IK/规划确实需要时再引入 |
| **Blender/BlenderProc** | 暂缓 | 只有真实数据不足、确需大规模合成数据时使用 |

### 7.2 不建议的软件堆叠

当前不建议同时把 Isaac Sim、MuJoCo、Gazebo、CoppeliaSim、RobotStudio 全部引入。

这些软件承担的任务有重叠，但物理模型、机器人描述、控制接口、碰撞几何和数据同步方式不同。多平台并行会增加模型维护和结果对齐工作量，却不一定增加论文贡献。

**建议当前主平台明确为 MuJoCo，真机明确为 CR10A。** 其他论文使用的仿真软件只作为文献比较和方法参考，不作为新增开发任务。

### 7.3 MuJoCo 应该承担什么

MuJoCo 不应只用于展示机械臂动画。当前论文应至少验证：

- CR10A 运动学模型和关节限制；
- 气动平行双指夹爪的开合几何；
- 夹爪与目标易拉罐的左右接触；
- 夹爪与邻近物体、料箱壁的碰撞；
- 接近、闭合、提升、撤离、放置；
- 失败后场景状态和目标实例是否正确更新。

仿真模型要尽量根据真实尺寸建立。蓝色料箱底部直接铺设的白色泡沫板厚度只有几毫米，不能在模型中擅自增加抬高平台。
